# Phase 2: S3 file storage

## What changes

The default local mode still works without an AWS account. Activate the `s3` Spring profile to replace LocalFileStore with S3FileStore. The Job API, CSV processor, repository and dispatcher interfaces remain the same.

Input objects use `uploads/<job-id>.csv`; report objects use `results/<job-id>.csv`. Uploaded filenames never become object keys. Objects remain private: the API downloads a completed report using its own AWS permissions and sends the CSV to the caller. Presigned URLs are not implemented.

The upload request waits for the input object to be stored before creating metadata and dispatching the job. Background processing then reads that object, generates a report, writes it to S3, and marks the job completed only after the write succeeds. Temporary storage failures during upload/download return 503 with a generic response; worker failures mark the job FAILED and are logged.

## Run against a real bucket later

1. Create an AWS account and sign in yourself. No account or bucket was created by this milestone.
2. Choose one AWS region and create a dedicated bucket in that region. Keep Block Public Access enabled, bucket owner enforced, and default encryption enabled.
3. Configure a local AWS profile with temporary credentials, preferably through IAM Identity Center. Do not paste access keys into the source, GitHub, or chat. The SDK uses its default credentials chain; later ECS task roles will supply credentials without code changes.
4. Allow only object reads and writes for the two prefixes. `infrastructure/s3-object-policy.example.json` is a template, not an applied policy. Replace YOUR_BUCKET before using it. Bucket creation, IAM role setup, deletion, and deployment are separate steps.
5. Set the configuration and run the application:

```powershell
$env:AWS_PROFILE = "your-configured-profile"
$env:AWS_REGION = "your-bucket-region"
$env:CLOUDSCALE_S3_BUCKET = "your-private-bucket-name"
./mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=s3"
```

You can also run the packaged JAR with `--spring.profiles.active=s3`. Missing region or bucket fails startup instead of silently falling back to local storage. Run without the profile to use local storage.

After upload, check both prefixes in the S3 console, poll the job status, and download the report through the API. For the sample fixture, verify revenue 1179.97 and one invalid row. A live AWS run is still pending until an account, bucket, and authorized credentials exist.

## Engineering decisions

- The synchronous SDK stages an input stream to a temporary file before upload. That supplies an exact content length and a replayable source for SDK retries without copying the whole upload into Java heap. The temporary file is deleted after success or failure. API uploads are still limited to 10MB; the machine needs temporary disk space.
- SDK network calls have connection, socket, per-attempt, and overall timeouts. SDK request retries do not constitute durable job retries: there is no persistent queue or recovery yet.
- Region and bucket are configuration, not constants. Credentials are resolved at runtime; no credential values are stored in the repository.
- The download stream must be closed so the HTTP connection is released. Report downloads remain buffered as byte arrays, consistent with Phase 1.
- Unit tests verify replayable uploads, cleanup, error translation, stream ownership, and bean selection. A real SDK HTTP test uses an in-process S3 protocol stub and fake credentials restricted to localhost. This checks PUT/GET requests and worker report generation, not AWS IAM, encryption, billing, or real service availability.

## Remaining limitations

Job metadata and dispatch still live in memory. Restarting loses job records even though S3 objects survive. Failed jobs or failures between storage and metadata creation can leave orphaned objects. Lifecycle retention, reconciliation, DynamoDB persistence, SQS, leases, durable retries and multi-instance workers are later milestones. No performance claims have been measured.
